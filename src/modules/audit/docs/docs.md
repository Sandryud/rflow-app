# Модуль `audit`

## Назначение

Модуль отвечает за неизменяемый журнал значимых бизнес-действий в контексте организации, проекта и релиза.

Audit log позволяет определить:

- какое действие произошло;
- над какой сущностью оно выполнено;
- какой пользователь выполнил действие;
- когда действие произошло;
- к какой организации, проекту и релизу относится событие;
- какой минимальный контекст действия сохранён в `metadata`.

## Основные обязанности

- хранить append-only события `AuditEvent`;
- возвращать события релиза с публичными данными actor;
- поддерживать стабильную cursor pagination;
- создавать событие через переданный Prisma transaction client;
- сохранять audit event атомарно с основной бизнес-операцией.

Значение `action` хранится строкой, поскольку набор событий расширяется и не должен требовать миграции Prisma enum для каждого нового действия.

Поле `metadata` хранит только контекст конкретного события и не используется как копия всей сущности.

## Что не относится к этому модулю

- принятие решений о допустимости lifecycle-перехода;
- проверка ролей для изменения release;
- изменение или удаление существующих AuditEvent;
- создание AuditEvent напрямую через HTTP API;
- автоматическое подключение аудита к use cases за пределами release lifecycle.

На текущем этапе запись события подключена ко всем реализованным переходам release lifecycle.

## Контекст использования

`ReleasesService` формирует event payload конкретного перехода. `ReleasesRepository` выполняет mutations состояния и передаёт тот же transaction client в `AuditRepository`.

Подключённые события:

| Action                     | Переход                | Дополнительная metadata |
| -------------------------- | ---------------------- | ----------------------- |
| `release.review_requested` | `DRAFT → IN_REVIEW`    | Нет                     |
| `release.approved`         | `IN_REVIEW → APPROVED` | Нет                     |
| `release.rejected`         | `IN_REVIEW → REJECTED` | Нет                     |
| `release.reopened`         | `REJECTED → DRAFT`     | `approvalsReset: true`  |
| `release.released`         | `APPROVED → RELEASED`  | Нет                     |

Если создание события завершается ошибкой, транзакция не фиксирует изменение release.

Чтение audit log доступно любому участнику организации, включая роль `VIEWER`.
